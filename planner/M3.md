## 🎯 Tujuan
User dapat membuat, melihat, mengubah, menyelesaikan, dan menghapus tugas pribadi, dilengkapi pencarian, filter, sorting, dan pagination.

## 📦 Deliverables
- `TaskRepository`, `TaskController`
- View `tasks/index`, `tasks/form`, partial kartu tugas & pagination
- Filter bar yang memakai custom dropdown kategori dari M2

## ✅ Task List

### 3.1 Repository
- [x] `TaskRepository`: `paginateByUser($userId, $filters, $page, $perPage)`, `findOwned()`, `create()`, `update()`, `delete()`, `toggle()`.
- [x] Semua query **otomatis difilter `user_id`** (tidak ada method tanpa filter user).
- [x] Filter: `q` (judul/deskripsi, case-insensitive via `mb_stripos`), `status`, `category` (termasuk "tanpa kategori"), `priority`.
- [x] Sorting whitelist: `created_at`, `due_date`, `priority`, `title`, arah `asc|desc`; nilai lain → default.
- [x] Pagination: `page`, `per_page` dibatasi 1–100 (default 10).
- [x] `completed_at` diisi saat status → `done`, di-`null` saat kembali ke status lain.
- [x] Read-modify-write dilakukan dalam `JsonStore::transaction` (**SEC-05**).

### 3.2 Controller & route (SPEC §4)
- [x] `GET /tasks` — daftar + filter + pagination.
- [x] `GET /tasks/create` & `POST /tasks` — buat tugas.
- [x] `GET /tasks/{id}/edit` & `POST /tasks/{id}/update` — ubah.
- [x] `POST /tasks/{id}/toggle` — selesai/belum.
- [x] `POST /tasks/{id}/delete` — hapus (modal konfirmasi di UI).
- [x] Validasi: title wajib 1–120; description ≤ 1000; status & priority whitelist; `due_date` valid (`checkdate`); `category_id` harus milik user atau kosong (**SEC-20/30**).
- [x] `user_id` selalu dari session, **abaikan** jika ada di input.
- [x] Pesan flash setelah tiap aksi (Post/Redirect/Get); nilai lama form di-escape saat validasi gagal.

### 3.3 UI
- [x] Kartu tugas: judul, deskripsi singkat, chip kategori berwarna, badge status & prioritas, tenggat; tugas lewat tenggat diberi penanda merah.
- [x] Strip warna kategori di sisi kartu; tugas selesai tampil dicoret/redup.
- [x] Form tugas memakai custom dropdown kategori; select status/prioritas bergaya brutalism (native `<select>` yang di-style atau komponen serupa).
- [x] Filter bar: input cari, dropdown kategori, status, prioritas, sort; tombol "Reset".
- [x] Empty state dengan CTA "Tambah Tugas Pertama".
- [x] Ringkasan di atas daftar (total, selesai, terlambat).
- [x] Responsif: 1 kolom (mobile), 2–3 kolom (desktop).
- [x] Modal konfirmasi hapus via JS eksternal (tanpa inline handler).

### 3.4 Kualitas
- [x] Parameter query dari URL dibersihkan dan dipertahankan di link pagination/sort (di-escape dengan `e()`/`http_build_query`).
- [x] Tidak ada N+1 berlebihan: peta kategori dimuat sekali per request.

## 🧪 Skenario Uji
| # | Skenario | Hasil yang diharapkan |
|---|---|---|
| 1 | Buat tugas lengkap | Tersimpan di `tasks.json` dengan ID `tsk_…`, timestamp UTC |
| 2 | Judul kosong / > 120 karakter | Ditolak, error inline |
| 3 | `due_date` = `2026-02-31` | Ditolak |
| 4 | `status=hacked` / `priority=urgent` | Ditolak (whitelist) |
| 5 | Pilih `category_id` milik user lain | Ditolak |
| 6 | Akses `/tasks/{id}/edit` tugas user lain | 404 + security log |
| 7 | Toggle selesai lalu batal | `completed_at` terisi lalu null |
| 8 | Hapus tugas | Hilang dari daftar & JSON |
| 9 | Cari "laporan", filter status+kategori, sort tenggat | Hasil sesuai, pagination benar |
| 10 | `?page=-1`, `?per_page=99999`, `?sort=; DROP` | Dinormalisasi/default, tanpa error |
| 11 | Judul/deskripsi berisi HTML/JS | Tampil sebagai teks, tidak dieksekusi |
| 12 | Dua tab menyimpan bersamaan | Data tidak korup, tidak ada tugas hilang |
| 13 | POST tanpa CSRF | 403 |
| 14 | 2 user berbeda | Masing-masing hanya melihat data sendiri |
