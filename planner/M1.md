## 🎯 Tujuan
User dapat mendaftar, login, dan logout dengan aman. Semua route privat terlindungi middleware auth.

## 📦 Deliverables
- `UserRepository`, `Auth`, `Csrf`, `Validator`, `RateLimiter`
- `AuthController` + view `auth/login`, `auth/register`
- Middleware auth & guest
- Seed 3 kategori default saat register

## ✅ Task List

### 1.1 Fondasi keamanan
- [x] `Csrf`: generate token per session, `verify()` dengan `hash_equals`, helper field hidden di view (**SEC-50**).
- [x] `Validator`: aturan `required`, `email`, `min`, `max`, `in`, `regex`; hasil berupa array error per field.
- [x] `RateLimiter`: counter berbasis file di `storage/ratelimit/`, kunci = hash(IP+email), 5 gagal/15 menit (**SEC-13**).
- [x] Middleware: `auth` (redirect `/login`), `guest` (redirect `/tasks`), `csrf` untuk semua POST.

### 1.2 Register (`GET/POST /register`)
- [x] Form: nama, email, password, konfirmasi password (+ token CSRF).
- [x] Validasi sesuai SPEC §5; email dinormalisasi lowercase, **unik**.
- [x] Hash dengan `password_hash()` (Argon2id, fallback bcrypt cost 12) (**SEC-10**).
- [x] Simpan user via `JsonStore::transaction` (cek unik email **di dalam lock**).
- [x] Seed kategori `Pribadi`, `Pekerjaan`, `Belajar` untuk user baru dalam proses yang sama.
- [x] Setelah sukses: redirect ke `/login` dengan flash sukses (atau auto-login + `session_regenerate_id(true)`).
- [x] Rate limit pada endpoint register.

### 1.3 Login (`GET/POST /login`)
- [x] Cek rate limiter sebelum verifikasi; lewat batas → 429.
- [x] `password_verify()`; jika email tidak ditemukan tetap verifikasi ke hash dummy (**SEC-12**).
- [x] Pesan error generik: "Email atau password salah."
- [x] Sukses → `session_regenerate_id(true)`, simpan **hanya** `user_id`, update `last_login_at`, reset counter, `password_needs_rehash` bila perlu (**SEC-14**).
- [x] Redirect ke `/tasks`. Parameter `?next=` (jika dipakai) hanya boleh path internal berawalan `/` dan bukan `//`.
- [x] Log event ke `security.log` (**SEC-71**), tanpa password.

### 1.4 Logout (`POST /logout`)
- [x] Wajib POST + CSRF. Kosongkan session, hapus cookie, `session_destroy()`.
- [x] Redirect ke `/login` dengan flash info.

### 1.5 Session lifecycle
- [x] Timeout idle 2 jam & absolute lifetime; session kedaluwarsa → redirect login.
- [x] `Auth::user()` memuat user dari JSON (tanpa mengekspos `password_hash` ke view).

### 1.6 UI
- [x] Halaman login & register bergaya neu brutalism, error inline per field, nilai lama di-escape.
- [x] Navbar menampilkan nama user (di-escape) + tombol logout (form POST).
- [x] Tampilan responsif mobile.

## 🧪 Skenario Uji
| # | Skenario | Hasil yang diharapkan |
|---|---|---|
| 1 | Register data valid | User tersimpan, password berupa hash (cek `users.json`), 3 kategori seed dibuat |
| 2 | Register email duplikat (beda huruf besar) | Ditolak dengan pesan error |
| 3 | Register password < 8 / konfirmasi beda | Ditolak, error inline |
| 4 | Login benar | Masuk, session ID berganti, redirect `/tasks` |
| 5 | Login salah (email tidak ada vs password salah) | Pesan **sama persis** |
| 6 | 6× login gagal berturut-turut | Percobaan ke-6 → 429 |
| 7 | POST tanpa/dengan token CSRF salah | 403 |
| 8 | Buka `/tasks` tanpa login | Redirect `/login` |
| 9 | Buka `/login` saat sudah login | Redirect `/tasks` |
| 10 | Logout via GET `/logout` | 404/405 (hanya POST yang diizinkan) |
| 11 | Register nama `<script>alert(1)</script>` | Tersimpan, tampil sebagai teks (escaped), tidak dieksekusi |
| 12 | Cek cookie | `HttpOnly`, `SameSite`, `Secure` (di HTTPS) |
